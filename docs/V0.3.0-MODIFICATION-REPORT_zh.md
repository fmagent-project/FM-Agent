# FM-Agent v0.3.0-dsh.1 修改报告

## 1. 修改范围

本版本以 `FM-Agent-release.zip` 为静态分析代码基线，将 OpenCode 后端替换为
DeepSeek Harness，删除动态验证/插装模块，并把运行时、模型兼容、trace、错误恢复、
报告和离线交付补全为可部署版本。

详细的逐项符合性见 `UPSTREAM-CONFORMANCE-ANALYSIS_zh.md`。

## 2. 后端替换与离线运行

### 新增

| 文件 | 用途 |
|---|---|
| `src/harness_backend.py` | 构造并执行 DeepSeek Harness headless 调用；统一 Agent 与结构化 LLM 路径 |
| `src/agent_trace.py` | Harness 进程生命周期、NDJSON 日志、proxy 日志关联和阶段终态事件 |
| `src/qwen_tool_parser.py` | Qwen XML/Hermes/JSON/畸形文本工具调用解析、白名单和 schema 校验 |
| `src/tool_compat_proxy.py` | 本地 loopback OpenAI-compatible 代理；移除服务端 tools 并转换文本工具调用 |
| `scripts/run_harness_with_tool_proxy.py` | 管理每个 Harness 会话对应的临时兼容代理 |
| `scripts/test_model_connectivity.py` | 纯文本、Bash、write JSON 三段真实模型验证 |

### 修改

- `src/llm_client.py`：所有结构化推理经 Harness，不再直接依赖原 OpenCode client；
- `config.py`、`fm-agent.toml`、`src/configure_llm.py`：增加后端、API style、
  `qwen-text/native` 配置和安全的独立 secret 文件；
- `src/env_check.py`：校验随包 Python、Harness、CodeGraph，不执行联网安装；
- `bin/fm-agent`：提供 configure、test-model、dashboard、report、verify-install、version。

## 3. OpenCode 和动态模块删除

完整移除：

```text
src/opencode_trace.py
src/cli_backend.py
src/agent_validation_core/
md/bug_validator.md
```

同时删除 `--bug-validator`、`--agent-validator*` 等只服务于动态验证、observable、
repair 或插装的选项。离线自检会检查这些模块不能被 import、归档中也不能存在。

## 4. 真实部署问题、根因和修复

| 问题 | 根因 | 修改 | 验证结果 |
|---|---|---|---|
| OpenCode 初始化卡住 | 初始化会访问在线资源 | 完全删除 OpenCode；Harness 和 Python 固定随包 | 断网安装及运行通过 |
| vLLM `--tool-call-parser mistral` 返回 422 | Qwen 工具 token/语法与 Mistral parser 不匹配 | qwen-text 代理移除上游 tools，以文本协议解析后还原 tool calls | 真实 `qwen3.6-35b-a3b` 的 Bash/write 往返通过 |
| `reasoning_content` 有值但 `content` 为空 | thinking 模式未给最终回答 | 首次请求即 `enable_thinking=false` + `/no_think`；仍为空时明确协议错误 | reasoning-only 回归通过 |
| Harness 退出 0 但阶段文件缺失 | 进程状态不代表 Agent 完成写入 | `agent_call` 与 `stage_validation` 分离；逐阶段验证产物/schema/覆盖 | Stage 1～6 假成功回归通过 |
| `_harness.log` 为空 | 只等最终文本，未保存流式事件 | Harness 强制 NDJSON；原始上游响应写入同前缀 proxy log | 所有测试日志非空 |
| Qwen 输出畸形 `<function=...>` 或伪 JSON | 模型学习到混合工具语法 | 平衡 JSON 恢复、宽容 XML/Hermes 解析；执行前仍做工具白名单和 schema 校验 | 多种畸形调用均完成 sidecar 写入 |
| `write.content` 中 JSON 被转换为对象 | 通用 JSON 解析忽略工具字段 schema | schema 声明为 string 时保持原始字符串 | JSON 文件写入和读回通过 |
| `verdict=MATCH`，理由却给出反例 | 模型结构化字段与自然语言结论矛盾 | 语义矛盾检查，记 `format_error` 并按原重试逻辑纠正 | 矛盾回归通过；“No counterexample exists”不误报 |
| 实际后置条件照抄业务期望 | 模型把规范性上下文当成代码已实现行为 | post-condition 明确以代码为权威；implication 再用代码反查 Condition A | 重复元素首索引缺陷成功检出 |
| 规约遗漏用户知识中的边界 | Agent 未稳定读取独立 knowledge 文件 | 用户知识全文嵌入 batch prompt，并保留原文件作为 trace 输入 | inclusive clamp 边界缺陷独立检出 |
| `ERROR` 被当作已完成 | resume 完成判断只看结果文件存在 | ERROR 属于 incomplete；报告为 PARTIAL；`--resume` 重新推理 | ERROR 终态回归通过 |
| Stage 6 报告少最后一条终态 | 报告先于最终 validation 写入 | 先写终态事件，再生成三种报告；失败同样先保留报告 | 报告内含 stage_6 终态 |

## 5. Stage 1～6 修改

### Stage 1

- 保留 `phases.json` schema 和 phase/module/source_files 结构；
- 每次尝试后验证 JSON、schema 和目标源码覆盖；
- 所有模型尝试失败时，确定性生成覆盖非测试源码的单阶段计划；
- fallback 会打印 WARNING 并写 trace，不伪装为模型生成。

### Stage 2

- 保留 engine overview、phase types 和用户领域知识布局；
- 明确列出缺失输出，不再只依赖 Harness 退出码；
- 模型调用与 Stage 1 使用同一个 qwen-text 解析链路。

### Stage 3～5

- 继续使用更新资料的本地确定性抽取、文件列表和 top-down layer；
- 增加阶段终态事件，便于仪表盘和错误报告统一展示；
- 不经过模型工具解析器。

### Stage 6

- 保留更新资料的 phase/layer/batch manifest、并发执行和重试；
- 所有实际读取文件在 trace `input_files` 中列出；
- 用户知识同时直接嵌入 batch prompt；
- sidecar 写入后验证 JSON 与 schema；
- 结构化 verification 使用 text-only Harness 路径，避免无意义工具循环；
- 每个函数输出 MATCH/MISMATCH/ERROR，并支持 `--all-bugs` 多候选。

## 6. 过程和错误展示修改

### Trace

`fm_agent/trace/events.jsonl` 现在区分：

```text
agent_call        Harness 进程调用
llm_call          post-condition / implication 结构化调用
stage_validation  阶段产物终态
```

payloads 中保存：

```text
*_harness.log                 Harness NDJSON
*_proxy.jsonl                 上游原始响应和解析决策
*_message_*_system.txt        结构化调用 system 输入
*_message_*_user.txt          结构化调用 user 输入
*_response.txt                最终结构化文本
```

proxy trace 不记录 Authorization 或 API key。

### Dashboard

- 恢复公共版 `--dashboard` 自动启动方式；
- 保留独立 `fm-agent dashboard <project>`；
- trace 被截断/重建时重置累计状态，避免重复计数；
- 分开显示最新产物终态与历史错误/重试；
- 显示最近 LLM/Harness 调用、阶段、静态 verdict、耗时和可获得的 tokens；
- 动态 bug 面板替换为静态推理面板，避免误称 confirmed bug。

## 7. 报告修改

公共版的动态 `report.html` 在用户更新资料中被删除。本版本新增静态报告链路：

- `src/verification.py` 生成稳定 JSON 和 Markdown；
- `report.py` 从终态静态产物生成自包含 HTML；
- `main.py` 在完整 Stage 6 后立即生成；
- `src/incremental_reasoner.py` 在增量静态分析后立即生成；
- `fm-agent report <project>` 可从现有产物重建。

HTML 对齐公共版体验，包含搜索、verdict 和源文件筛选、排序、展开/折叠、完整详情、
产物链接、源码行号/范围高亮、错误及 trace 诊断。标签改为静态语义：
`MISMATCH` 永远只表示未动态确认候选。

## 8. 普通非 Git 项目修改

- `_is_git_repo` 不再把普通目录视为致命错误；
- full pipeline 可直接运行；
- `--isolate` 对 Git 使用冻结 worktree，对普通目录使用文件系统副本；
- 结果始终回写项目的 `fm_agent/`；
- `--incremental` 仍明确要求 Git commit 基线；
- 在 PATH 中没有 git 的测试环境仍可完成普通目录 full/isolate。

## 9. 离线交付修改

归档固定包含：

- Python 3.12.14 运行时和 Python 依赖；
- DeepSeek Harness `0.1.6-alpha.1`；
- CodeGraph `1.6.0-fmagent.1`；
- ArkTS/tree-sitter 等语言运行依赖；

验证包内文件，外层 `.sha256` 验证归档。

## 10. 验证证据

### 自动回归

- qwen-text 正常、XML、Hermes、严格 JSON、伪 JSON、缺失闭合标签；
- reasoning-only、空 content、未知工具、未解析工具语法安全失败；
- Stage 1～6 普通非 Git 端到端；
- ERROR/PARTIAL/resume；
- verdict/reason 矛盾纠正；
- 报告 Stage 6 终态、源码位置和主要交互标记；
- 无 git 普通目录和 isolate；
- 包内 OpenCode/动态模块缺失检查。

### 真实模型

模型：`qwen3.6-35b-a3b`，qwen-text 模式。

```text
FM_AGENT_MODEL_CONNECTIVITY_OK
FM_AGENT_MODEL_TOOL_OK
```

不含 `Contract:` 注释的普通 C 项目中：

- 检出重复元素首索引错误；
- 检出折扣执行顺序错误；
- 检出整数平均值溢出；
- 独立新工作区检出 clamp inclusive 上界错误；
- 正确的饱和求和保持 MATCH；
- clamp 独立运行 30 条 proxy 记录全部 HTTP 200，未解析工具调用、reasoning-only、
  非 200 均为 0。

### 目标系统

- Ubuntu 22.04.5 x86_64；
- glibc 2.35；
- 独立 network namespace，`/proc/net/route` 只有表头；
- 安装前 full 自检、安装、安装后 full 自检全部通过。

## 11. 最终语义边界

本版本报告的是静态候选，不运行被分析程序，不能取代公共版动态确认结论。不存在
动态测试的情况下，最正确的兼容方式是保留相似的过程、错误、证据和报告体验，同时
把 `MISMATCH` 与 `confirmed bug` 明确区分。本版本没有伪造动态结果。
